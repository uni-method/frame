# Типы

`type` атрибута и `typeSpec` фильтра парсятся `TypeSpecParser`. Распознаются:

| Запись                                        | Вид        |
| --------------------------------------------- | ---------- |
| `string`                                      | строка     |
| `int`, `integer`                              | целое      |
| `float`, `double`, `real`                     | дробное    |
| `bool`, `boolean`                             | булево     |
| `datetime`, `\DateTimeImmutable`, `\DateTime` | дата-время |
| `uuid`                                        | UUID       |

Входное значение `datetime` (тело запроса и фильтры list-действия) — только
абсолютный ISO 8601 (профиль RFC 3339): `2026-01-31`, `2026-01-31T10:15:00`,
с дробной частью секунд до 6 цифр и/или смещением `Z` либо `±hh:mm`
(`2026-01-31T10:15:00.000Z` — формат `Date.prototype.toISOString()`).
Относительные значения (`now`, `+1 day`), разделитель-пробел, аббревиатуры и
идентификаторы зон (`EST`, `Europe/Moscow`) отклоняются (422 в теле, 400 в
фильтре). Значение **без смещения** трактуется в таймзоне PHP по умолчанию
(`date.timezone` / `date_default_timezone_set()`); дата без времени — полночь
в этой таймзоне.

Модификаторы:

- суффикс `[]` — список (`string[]`, `int[]`);
- `|null` или `null|` — nullable (`string|null`, `int[]|null`).

Суффикс `[]` работает не только в `typeSpec` фильтра, но и в `type` любого
атрибута модели — например `type: "int[]"` или `type: "string[]|null"`. Парсер
один и тот же (`TypeSpecParser`), поэтому правила идентичны.

Важно: `[]` задаёт список элементов **одного из перечисленных скалярных видов**
(string/int/float/bool/datetime/uuid). Списка объектов или произвольных мап
(например JSON-структуры со вложенными объектами) этим выразить нельзя —
типов `array`, `json`, `object`, `mixed` парсер не знает и бросает
`UnknownTypeException`. Данные, которые на стороне сущности являются массивом
объектов или ассоциативной мапой (типичный случай — поле, кастуемое из JSONB
через typecast), как атрибут модели не описываются: их следует либо исключить из
модели, либо нормализовать в отдельные сущности и описать через связи
(`oneToMany`/`oneToOne`). Связь `*ToMany` отдаётся и принимается как обычный
PHP-массив объектов целевой модели — см. раздел про getter/setter связей.

Неизвестный тип в `typeSpec` приводит к ошибке загрузки. Тип, не входящий в
список, в обычном `type` атрибута на этапе загрузки не отвергается, но
используется маппером/кастером, поэтому держитесь поддерживаемых значений.
