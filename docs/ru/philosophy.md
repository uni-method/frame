# Философия

Фреймворк превращает HTTP-запрос к модели в вызов прикладного кода и обратно.
Конфиг описывает **что** (модели, атрибуты, связи, действия); прикладной код —
**как**: какие классы и интерфейсы вы реализуете под этот конфиг. Остальное —
разбор запроса, маппинг, проверки структуры, мутаторы, сборка ответа — делает
фреймворк.

## Принципы

- **Конфиг — контракт.** `schema` описывает, что есть и что разрешено; `impl` —
  чем это реализовано. Всё, что клиент может прислать или запросить, заявлено
  в конфиге явно: `writable`, `includable`, `config.filters`, `config.sort` —
  вайтлисты. См. [domains/config.md](domains/config.md),
  [domains/actions.md](domains/actions.md), [domains/list.md](domains/list.md).
- **Строгость вместо тихих пропусков.** Незаявленное поле, оператор, связь —
  ошибка клиента (400/422), а не молча отброшенные данные. Рассинхрон конфига и
  кода ловится на старте bootstrap-валидацией, а не на первом запросе.
- **Декларация входа.** На create/update `?included=` — обязательство: тело
  обязано ему соответствовать. См. [domains/actions.md](domains/actions.md).
- **Fail-closed.** Без провайдера пользователя нетривиальный `access` запрещён.
  См. [domains/access.md](domains/access.md).
- **Каждой проверке — своё место.** Правило живёт в ограничении на объекте,
  сейвер — только побочные эффекты, локатор — только поиск по id. См.
  [domains/constraints.md](domains/constraints.md),
  [usage/validation-patterns.md](usage/validation-patterns.md),
  [usage/persistence-strategy.md](usage/persistence-strategy.md).
- **Ошибки по категориям.** Доменные — детерминированы вводом клиента и дают
  4xx; ошибки конфигурации и сбои уходят на границу приложения и дают 500. См.
  [domains/errors.md](domains/errors.md).
- **Без навязанной инфраструктуры.** Entity — обычный PHP-класс, ORM не
  навязан; фреймворк обращается к нему через getter/setter или публичные
  свойства. См. [domains/models.md](domains/models.md).
- **Без запросного состояния.** Сервисы можно держать синглтонами в
  долгоживущем воркере. См. [usage/getting-started.md](usage/getting-started.md).

## Что вы пишете, а что фреймворк делает сам

Фреймворк берёт на себя разбор запроса, маппинг данных в ваши объекты и обратно,
валидацию структуры относительно конфига, применение мутаторов по фазам и сборку
ответа. От вас требуется предоставить «края» этого конвейера:

- **Entity-классы** — ваши доменные объекты (то, что в конфиге `impl.models[*].class`).
- **Persistence-реализации** — как находить, сохранять, удалять и листать сущности
  (`EntityLocatorInterface`, `EntitySaverInterface`, `EntityRemoverInterface`,
  `EntityCollectionInterface`).
- **Проверка ограничений** — адаптер к вашей библиотеке валидации
  (`ConstraintCheckerInterface`); фреймворк вызывает его в фиксированных фазах
  с контекстом (см. [domains/constraints.md](domains/constraints.md)).
- **Провайдер пользователя** — кто текущий пользователь и что ему можно
  (`UserProviderInterface`), если используете контроль доступа.
- **Мутаторы** (опционально) — преобразования значений по фазам
  (`AttributeMutatorInterface`, `RelationMutatorInterface`).
- **Граница приложения** — точка входа, которая вызывает `ApiService::execute`,
  ловит несведённые исключения (отдельно — ошибки конфигурации) и оформляет 500
  (см. [domains/errors.md](domains/errors.md)).

Часть классов для list-действий (`{Model}Filter`, `{Model}Sort`,
`{Model}Pagination` и классы операторов) **генерируется** по конфигу — вы их не
пишете руками, но должны знать соглашения об именах, чтобы понимать ошибки и
писать валидацию (см. [domains/list.md](domains/list.md)).

## Структура ответственности
```
JsonConfigLoader
├── Проверка структуры JSON
├── Проверка существования id getter
├── Проверка валидности locators
└── Создание Config

ActionValidator
├── Проверяет action / model / relation / writable / include
├── Проверяет разрешённость режимов (reference/update/create)
└── Не трогает конкретные id, не ищет сущности

MappingToObject
├── Строит объекты по Config
├── Определяет id и поля
├── Проверяет существование сущностей по id (через locators)
└── Применяет кастинг типов и setter-ы
```
